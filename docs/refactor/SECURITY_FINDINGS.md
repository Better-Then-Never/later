# SECURITY_FINDINGS.md

History was **not** rewritten in this refactor (hard rule). Items marked *rotate* need action by the project owner. No secret value is reproduced in this file.

| # | Finding | Where | Risk | Status / action |
|---|---|---|---|---|
| SEC-01 | Google Maps API key committed in plain text | `android/app/src/main/AndroidManifest.xml`, `ios/Runner/AppDelegate.swift` (and therefore in git history) | Key abuse / quota theft if the key is not restricted | Moved out of tracked files in this refactor (Android: `local.properties` → manifest placeholder; iOS: git-ignored xcconfig → Info.plist). **Rotate the key** in Google Cloud Console and restrict it (Android apps: package `com.example.later` + SHA-1 of every signing key; iOS apps: bundle id; APIs: Maps SDK for Android/iOS only). |
| SEC-02 | Firebase client config (`google-services.json`, `firebase_options.dart`) was committed and later stripped by a force-push | git history (old commits on GitHub forks/clones) | Low on its own (Firebase API keys are identifiers), high together with permissive rules | Teammates already re-registered the apps. Keep the files git-ignored (done). Make sure rules (SEC-04) are deployed. Consider App Check. |
| SEC-03 | Firebase Android API key had no visible app restriction issues, but the Maps key rejects the debug SHA-1 `FE:77:7D:3A:…` | Cloud Console | Maps unusable in debug builds of developers whose SHA-1 is not registered | See BLOCKERS.md B-01. |
| SEC-04 | Firestore rules in the repo are expired test-mode rules; production rules are unknown and, given the client code, must allow: reading every user's email and FCM token, reading every capsule including private ones, editing any user's `friends` array and writing into any user's `notifications`/`followers` | `firestore.rules` | Data exposure, account tampering (anyone can "befriend" themselves into anyone's friends list and then read their friends-only capsules) | Rewritten least-privilege rules + 31 tests (`tools/rules-tests`, commit 76e3a75). **Not deployed.** Deploy last, in the order given in MIGRATIONS_NEEDED.md §1 (`firebase deploy --only firestore:rules,storage`). |
| SEC-05 | Storage rules in repo deny everything; production unknown | `storage.rules` | Same as above for images | Rewritten owner-only write rules with type/size limits + tests (76e3a75). Not deployed (see SEC-04). |
| SEC-06 | Public HTTPS function `getUserData` returns the **email** of any uid and calls `makePublic()` on the user's profile image | `functions/index.js` | Email harvesting by uid; permanent public image URLs | Fixed in code (b0ea48e: display name + token URL of the avatar only), with tests. Not deployed (MIGRATIONS_NEEDED.md §1). Images already made public stay public until their ACL is reset (MIGRATIONS_NEEDED.md §3, manual). |
| SEC-07 | Users' email and FCM token stored in the publicly readable `users/{uid}` document | client code | Privacy | New writes no longer store them there (`users/{uid}/fcmTokens/*`, email read from Auth). Existing fields are removed by `tools/migrations/migrate.js` (dry run by default; MIGRATIONS_NEEDED.md §2). Not run against production. |
| SEC-08 | Username availability checked by an unauthenticated query | signup | Forces world-readable `users` | Replaced by an authenticated transaction on `usernames/{username}`. |
| SEC-09 | FCM token never removed on logout → next user of the device receives the previous user's notifications | push service | Privacy | Fixed: token document deleted and FCM token revoked on sign-out. |
| SEC-10 | Debug logging printed FCM tokens and user ids | `print()` calls | Token leakage via logcat | All `print()` removed; logger redacts tokens. |
| SEC-11 | Android activity declared `showWhenLocked`/`turnScreenOn` | manifest | App content visible over the lock screen | Removed (not a feature of the app). |
| SEC-12 | No App Check | Firebase | API abuse with the public config | Not added (new feature) — recommended in REPORT.md next steps. |
